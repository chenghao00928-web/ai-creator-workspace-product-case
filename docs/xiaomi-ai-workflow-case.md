# 小米 AI 产品经理实习岗位匹配案例

## 1. 岗位理解

小米这个 AI 产品经理实习岗位更强调“AI 产品工作流助理”能力，而不是只做传统需求文档。岗位核心可以拆成 5 类任务：

| 岗位任务 | 能力要求 | 本项目对应产出 |
|---|---|---|
| 产品文档 AI 协作 | 用 AI 辅助竞品分析、PRD、交互说明和传播文案 | `docs/competitor-analysis.md`、`docs/prd.md`、`docs/prompt-design.md` |
| AI 工作流搭建与优化 | 维护 Prompt 模板、知识库、pipeline 效果追踪 | `docs/prompt-template-library.md`、`scripts/batch-jd-analysis.js` |
| 可复用资产沉淀 | 将有效方法沉淀为 SOP、评估标准、自动化脚本 | 本文的 SOP 和评估清单 |
| 新场景探索与验证 | 发现团队中可用 AI 提效的新场景 | JD 分析、简历改写、面试问题生成、成本测算 |
| 跨工具流程维护 | 协同文档模板、同步流程、脚本工具等基础设施 | README、Demo Walkthrough、批量分析脚本 |

一句话概括：

> 这个岗位需要能把 AI 从“个人聊天工具”变成“团队可复用的产品工作流资产”。

## 2. 本项目如何匹配岗位

### 2.1 产品文档 AI 协作

本项目不是只写一个 Demo，而是把 AI 产品经理常见文档串成完整链路：

1. 竞品分析：拆解豆包、Kimi、通义千问、即梦 AI、ChatGPT、Claude、Gemini 的定位、交互和商业化。
2. 用户研究：从求职学生、创作者、运营、证券新人等用户中提炼共性痛点。
3. PRD 初稿：定义页面、字段、状态、异常和验收标准。
4. Prompt 设计：把自由聊天收敛为稳定结构化输出。
5. API 接入：用 Express + OpenAI SDK 调用 DeepSeek API。
6. 成本测算：补充多模型 token 成本，对比不同模型的商业化压力。

对小米岗位的讲法：

> 我可以用 AI 辅助产品文档生产，但不会停留在“让模型写文档”。我会把输入字段、输出结构、评估标准、成本口径和后续复用方式一起设计出来，让文档产出更稳定。

### 2.2 AI 工作流搭建与优化

本项目可抽象成一个 AI 产品工作流：

```text
岗位 JD / 用户背景
  -> 结构化表单输入
  -> Prompt 模板拼装
  -> 服务端 API 调用
  -> Markdown 结果输出
  -> 前端展示 / 复制 / 本地保存
  -> 成本测算 / Prompt 复盘 / 模板迭代
```

可优化点：

| 环节 | 当前实现 | 后续优化 |
|---|---|---|
| Prompt 输入 | 表单 + checkbox | 增加岗位类型、行业、简历版本、目标公司 |
| 模型调用 | 单模型 DeepSeek | 按任务难度自动选择低成本或高质量模型 |
| 输出展示 | Markdown 展示 | 解析为职责、差距、建议、问题等结构化卡片 |
| 质量评估 | 人工检查 | 增加完整性、具体性、可执行性评分 |
| 历史复用 | localStorage | 升级为岗位项目看板和简历版本管理 |
| 批量任务 | 手动单次分析 | 使用 `scripts/batch-jd-analysis.js` 批量处理多个 JD |

### 2.3 可复用资产沉淀

本项目已经可以沉淀为 4 类资产：

| 资产类型 | 示例 | 价值 |
|---|---|---|
| Prompt 模板 | JD 解析、竞品分析、PRD 初稿、面试问题生成 | 降低重复写 Prompt 的成本 |
| SOP | 从 JD 输入到结果保存的操作步骤 | 让新人也能稳定复现 |
| 评估标准 | 完整性、准确性、具体性、可执行性、风险边界 | 避免 AI 输出空泛或不可用 |
| 自动化脚本 | 批量 JD 分析、成本汇总 | 减少人工复制粘贴 |

对小米岗位的讲法：

> 我会把一次项目里验证有效的方法，沉淀成 Prompt 模板、SOP、评估标准和脚本工具，而不是只留在个人经验里。

## 3. 小米投递版项目讲述

### 3.1 60 秒版本

我准备的项目是一个 AI 求职工作台 Demo，但我会从“AI 产品工作流”的角度讲。项目从 AIGC 竞品分析和用户研究出发，发现求职学生真正需要的不是一次性回答，而是从岗位 JD 拆解、能力差距判断、简历表达改写到面试准备的连续流程。

所以我把这个流程做成了一个可运行 Demo：前端用表单降低 Prompt 输入门槛，后端通过 Express 调用 DeepSeek API，输出结构化 Markdown，并支持复制和本地历史保存。为了体现产品经理的成本意识，我还补充了 DeepSeek、OpenAI、Claude、Gemini、Kimi、通义千问、豆包等模型的 token 成本测算。

针对小米这个岗位，我进一步把项目沉淀成 Prompt 模板库、Demo Walkthrough、批量 JD 分析脚本和质量评估清单。也就是说，这个项目不是单纯展示一个 AI 功能，而是展示我能把 AI 工具转化成团队可复用的工作流资产。

### 3.2 面试可展开问题

**问：你如何判断 AI 输出质量？**

可以从 5 个维度回答：

1. 完整性：是否覆盖岗位职责、能力关键词、差距、简历建议、面试问题。
2. 具体性：是否基于 JD 原文和用户背景，而不是泛泛建议。
3. 可执行性：是否能直接转化为简历修改、学习计划或面试准备。
4. 边界感：是否避免编造经历，是否提醒用户人工确认。
5. 一致性：相同输入多次生成时，结构是否稳定。

**问：如果让你优化团队 AI 工作流，你会怎么做？**

可以按这 5 步回答：

1. 盘点高频重复任务，例如竞品分析、PRD 初稿、周报、用户反馈归类。
2. 把任务拆成输入、处理、输出、评估、复用 5 个环节。
3. 对每类任务沉淀 Prompt 模板和输出结构。
4. 建立质量评估标准，例如完整性、准确性、可读性、可执行性。
5. 用脚本或轻量工具处理批量任务，减少人工复制粘贴。

**问：你写过脚本或做过自动化吗？**

可以结合 `scripts/batch-jd-analysis.js` 回答：

> 我写了一个 Node.js 批量 JD 分析脚本，可以读取 JSON 文件中的多条岗位信息，调用本地 Demo 的 `/api/analyze-jd` 接口，并把每条结果保存成 Markdown。这个脚本体现的是把单次 AI 调用扩展成批量工作流的思路。

## 5. 简历项目描述建议

### 版本 A：偏 AI 产品工作流

AI 求职工作台 Demo：基于用户研究和 AIGC 竞品分析，设计 JD 解析、能力差距识别、简历改写建议和面试问题生成链路；使用 Node.js + Express + DeepSeek API 完成可运行 Demo，沉淀 Prompt 模板、PRD、Demo Walkthrough、批量 JD 分析脚本和多模型 Token 成本测算，形成从需求分析、Prompt 设计、API 接入到工作流复用的完整 AI 产品实践。

### 版本 B：偏小米岗位关键词

围绕 AI 产品经理实习岗位，搭建 AI 求职工作台作品集：使用 Claude/Codex/Gemini 等 AI 工具辅助竞品分析、PRD 初稿和 Prompt 模板设计；通过 DeepSeek API 实现 JD 分析 Demo，并补充批量分析脚本、质量评估清单和成本测算表，展示 AI 工作流搭建、Prompt 资产沉淀、自动化处理和产品文档协作能力。
