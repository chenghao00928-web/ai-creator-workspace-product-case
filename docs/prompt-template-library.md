# Prompt 模板库

## 1. 模板库目标

本模板库用于沉淀 AI 产品经理常用工作流中的 Prompt 资产，覆盖求职分析、竞品分析、PRD 初稿、Prompt 评估、输出质检和批量任务等场景。

使用原则：

- 每个 Prompt 都必须明确输入、输出结构和质量标准。
- 尽量减少空泛问题，要求模型基于用户提供的信息回答。
- 对不确定信息要求模型标注“需要补充”，避免编造。
- 输出优先使用 Markdown 表格、清单和分模块结构，便于复制到文档。

## 2. JD 解析 Prompt

### 适用场景

求职岗位分析、能力关键词提炼、简历改写方向判断。

### 输入字段

| 字段 | 说明 |
|---|---|
| target_role | 目标岗位 |
| company | 公司名称 |
| job_description | 岗位 JD |
| user_background | 用户背景 |
| focus_areas | 输出重点 |

### Prompt

```text
你是一名 AI 产品经理求职辅导助手。请基于我提供的岗位 JD 和个人背景，完成结构化岗位分析。

要求：
1. 不要编造我没有提供的经历。
2. 每个建议都要尽量对应 JD 中的具体要求。
3. 如果信息不足，请标注“需要补充的信息”。
4. 输出使用 Markdown。

目标岗位：
{target_role}

公司：
{company}

岗位 JD：
{job_description}

个人背景：
{user_background}

请输出以下模块：
1. 岗位核心任务
2. 能力关键词
3. 我的匹配点
4. 我的短板
5. 简历改写建议
6. 可补充的作品集材料
7. 面试可能问题
8. 需要补充的信息
```

### 质量标准

| 维度 | 标准 |
|---|---|
| 完整性 | 是否覆盖 8 个模块 |
| 具体性 | 是否引用 JD 中的具体任务 |
| 可执行性 | 是否能转化为简历修改和作品集补充 |
| 边界感 | 是否避免编造经历 |

## 3. 岗位匹配分析 Prompt

### 适用场景

针对目标岗位做定制化项目包装，适合投递前梳理项目证据、简历表达和面试讲述。

### Prompt

```text
你是一名 AI 产品经理面试辅导助手。请根据以下岗位要求和我的项目，帮我判断如何包装项目，使其更匹配目标岗位。

岗位要求重点：
{job_requirements}

我的项目：
{project_description}

请输出：
1. 岗位最看重的 5 个能力
2. 我的项目中可对应的证据
3. 需要补充的材料
4. 简历项目描述改写
5. 面试讲述稿，控制在 60 秒
6. 面试官可能追问的问题和回答要点

要求：
- 直接指出短板，不要只夸优点。
- 简历描述要像真实候选人写法，不要堆术语。
- 回答中要体现 AI 工具实操、Prompt 模板、API 接入、成本意识、质量评估和可复用资产。
```

## 4. 竞品分析 Prompt

### 适用场景

快速产出竞品分析初稿，适合 AIGC 产品、AI 助手、工作台类产品。

### Prompt

```text
你是一名 AI 产品经理。请基于以下竞品信息，输出一份结构化竞品分析。

分析目标：
{analysis_goal}

竞品列表：
{competitors}

统一测试任务：
{test_tasks}

请输出：
1. 竞品定位对比
2. 核心用户与场景
3. Prompt 引导方式
4. 生成结果质量
5. 二次编辑能力
6. 历史管理和资产复用
7. 会员体系和商业化
8. 对本项目的启发
9. 可借鉴点和风险点

要求：
- 不要编造未提供的具体数据。
- 如果需要进一步体验产品，请列出补充调研清单。
- 输出表格优先。
```

## 5. PRD 初稿 Prompt

### 适用场景

将产品想法转成 PRD 初稿，适合低保真阶段。

### Prompt

```text
你是一名产品经理，请根据以下产品背景生成 PRD 初稿。

产品名称：
{product_name}

目标用户：
{target_users}

核心痛点：
{pain_points}

MVP 范围：
{mvp_scope}

请输出：
1. 产品定位
2. 目标用户
3. 用户场景
4. 用户流程
5. 功能列表和优先级
6. 页面结构
7. 字段说明
8. 状态和异常
9. 验收标准
10. 后续迭代方向

要求：
- MVP 范围要克制，不要把所有功能都放进 P0。
- 每个功能都要说明用户价值。
- 验收标准要可检查。
```

## 6. Prompt 评估 Prompt

### 适用场景

检查某个 Prompt 的稳定性和可复用性。

### Prompt

```text
你是一名 Prompt 评估助手。请评估以下 Prompt 是否适合沉淀为团队模板。

Prompt：
{prompt_text}

使用场景：
{scenario}

请从以下维度评分，每项 1-5 分，并给出修改建议：
1. 输入字段是否清晰
2. 输出结构是否稳定
3. 是否限制模型编造
4. 是否便于复用
5. 是否有质量评估标准
6. 是否容易被新同学理解

最后输出：
- 总分
- 最大风险
- 建议改写版本
```

## 7. AI 输出质检 Prompt

### 适用场景

对模型输出进行人工交付前检查，适合 PRD、竞品分析、JD 分析等文档。

### Prompt

```text
请作为 AI 输出质检助手，检查以下内容是否适合交付给产品团队或面试官。

原始任务：
{task}

AI 输出：
{ai_output}

请检查：
1. 是否完整回答任务
2. 是否有明显空泛表达
3. 是否存在无依据判断
4. 是否有需要人工核验的信息
5. 是否结构清晰
6. 是否可以直接复制到文档

输出格式：
| 问题 | 严重程度 | 修改建议 |

最后给出一个交付判断：
- 可以交付
- 修改后交付
- 不建议交付
```

## 8. 批量 JD 分析 Prompt

### 适用场景

配合 `scripts/batch-jd-analysis.js` 批量分析多个岗位。

### Prompt

```text
请分析以下求职信息，并重点关注：{focusAreas}。

目标岗位：
{targetRole}

公司：
{company}

岗位 JD：
{jobDescription}

用户背景：
{userBackground}

请输出结构化、具体、可执行的求职分析。简历改写建议需要包含改写方向和示例表达；面试问题需要覆盖 AI 产品理解、用户研究、数据分析、项目经历和岗位匹配。
```

## 9. SOP：从单次 Prompt 到团队模板

1. 记录一次成功输出的完整输入和输出。
2. 抽象出固定输入字段，例如目标用户、任务背景、输出格式。
3. 删除一次性信息，保留可复用结构。
4. 增加约束条件，例如“不编造”“信息不足时标注”。
5. 增加质量评估标准。
6. 用 2-3 个不同案例测试模板稳定性。
7. 把模板沉淀到文档库，并注明适用场景和风险。
