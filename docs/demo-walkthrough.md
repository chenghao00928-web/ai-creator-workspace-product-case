# Demo 演示讲解与验收清单

## 1. 演示目标

这个 Demo 用来证明项目不是停留在产品分析文档，而是已经把用户需求、PRD、Prompt 设计、API 接入和异常处理串成了一个可运行的 AI 产品原型。

面试或作品集展示时，建议把它定位成：

> 面向 AI 产品经理实习求职者的 JD 分析与简历优化工作台，帮助用户把岗位要求转化为能力关键词、差距判断、简历表达和面试准备问题。

## 2. 演示前准备

1. 确认根目录存在 `.env`，并填写 `DEEPSEEK_API_KEY`。
2. 在 `server` 目录执行 `npm install`。
3. 在 `server` 目录执行 `npm run dev`。
4. 打开 `http://localhost:3000`。
5. 准备一份真实 AI 产品经理实习岗位 JD，以及一段个人背景。

如果没有真实 API Key，也可以只展示前端交互、字段设计、异常提示和 Prompt 设计说明。

## 3. 推荐演示路径

### Step 1：讲项目背景

先用 20 秒说明为什么做这个产品：

- AIGC 产品很多，但求职学生真正困难的不是“生成一段文字”，而是不知道如何拆解岗位要求、识别能力差距，并把自己的经历转成岗位匹配表达。
- 因此项目从泛 AI 创作助手收窄到 AI 求职工作台 MVP，选择 JD 分析作为首个高价值场景。

### Step 2：展示输入设计

在左侧输入区强调 3 个关键字段：

- 目标岗位：明确分析对象，避免泛泛输出。
- 岗位 JD：提供职责、要求和加分项，让模型有具体依据。
- 个人背景：帮助模型判断匹配度和简历表达方向。

输出重点使用 checkbox，是为了把 Prompt 选择变成表单化交互，降低用户写 Prompt 的门槛。

### Step 3：生成分析结果

点击“填入示例”或粘贴真实 JD 后生成分析。讲解时重点看结果是否覆盖：

- 岗位核心职责
- 能力关键词
- 用户背景匹配分析
- 能力差距
- 简历改写建议
- 面试可能问题
- 下一步学习建议
- 风险提示

这里可以强调：输出不是聊天式回答，而是固定结构化结果，方便用户继续修改、复制和保存。

### Step 4：展示本地历史

点击“保存到本地历史”，说明这个功能对应“求职投递项目管理”的雏形：

- 用户可以按岗位保存多次分析。
- 后续可扩展为岗位看板、简历版本管理、投递状态管理。
- 当前阶段先用 localStorage 做轻量验证，避免过早引入账号系统和数据库。

### Step 5：展示后端和安全设计

说明前端不会直接暴露 API Key，所有模型请求都通过服务端接口：

- 前端调用 `/api/analyze-jd`。
- Express 服务端读取 `.env`。
- 使用 OpenAI SDK 调用 DeepSeek OpenAI-compatible API。
- 当缺少 API Key、输入为空、模型返回为空或请求失败时，服务端返回明确错误。

## 4. 60 秒讲述稿

这个项目是一个面向 AI 产品经理实习投递的 AIGC 产品作品集。我先做了国内外 AI 产品的竞品分析和用户访谈，发现求职学生使用 AI 的核心痛点不是不会提问，而是不知道如何把岗位 JD 拆成能力要求，并把自己的经历表达成岗位匹配的语言。

所以我把最初的泛创作助手收窄成 AI 求职工作台 MVP。Demo 中用户输入目标岗位、岗位 JD 和个人背景后，系统会输出岗位职责、能力关键词、匹配分析、能力差距、简历改写建议和面试问题。前端用表单和 checkbox 降低 Prompt 门槛，后端通过 Express 调用 DeepSeek API，并把 API Key 放在服务端，避免前端泄露。

这个作品展示的是一条完整的 AI 产品经理工作链路：从竞品分析、用户研究、需求收敛，到 PRD、原型、Prompt 设计、API 接入、成本测算和商业化思考。

## 5. 验收清单

### 前端验收

- 首页可以正常加载，无明显中文乱码。
- 表单字段、按钮、历史记录区文案清晰。
- 点击“填入示例”后，目标岗位、岗位 JD、个人背景均被填充。
- 未生成结果时点击“复制结果”或“保存到本地历史”，会出现友好错误提示。
- 点击“清空内容”后，输入和结果区恢复初始状态。

### 接口验收

- `GET /api/health` 返回 `ok: true`。
- 未配置 `DEEPSEEK_API_KEY` 时，`POST /api/analyze-jd` 返回明确配置错误。
- 缺少必填字段时，`POST /api/analyze-jd` 返回 400。
- 输入过长时，`POST /api/analyze-jd` 返回 400。
- 模型请求成功时，返回 `result`、`model` 和 `usage`。

### 作品集验收

- README 能说明项目定位、亮点、运行方式和展示路径。
- 文档能覆盖竞品分析、用户研究、PRD、Prompt、API、商业化。
- Demo 能证明项目具备可运行能力，而不只是静态文档。
- 面试讲述能清楚解释为什么选择 JD 分析作为 MVP 场景。
