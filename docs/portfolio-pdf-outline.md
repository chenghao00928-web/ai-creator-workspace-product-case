# 作品集 PDF 大纲

## 1. 使用目标

本大纲用于将「AI 创作助手工作台」整理成一份适合投递 AI 产品经理实习岗位的作品集 PDF。

建议页数：12-15 页。

建议定位：

> 一个从用户研究、竞品分析、需求优先级、PRD、原型设计到商业化测算的 AI 产品经理完整项目 Case。

面向对象：

- AI 产品经理实习招聘方
- 产品经理面试官
- 校招/实习简历附件审阅者

## 3. 单页内容建议

### 第 1 页：封面

标题：

> AI 创作助手工作台产品方案设计

副标题：

> 面向 AI 产品经理实习岗位的 AIGC 产品作品集项目

建议包含：

- 姓名
- 西安交通大学 应用统计研一
- 目标岗位：AI 产品经理实习
- 关键词：AIGC / 用户研究 / 竞品分析 / PRD / 原型 / 商业化
- GitHub 项目链接

### 第 2 页：项目背景与问题

核心表达：

当前用户使用通用 AI 工具时，流程常停留在“输入 Prompt - 复制结果 - 到其他工具修改”，导致输入门槛高、结果难交付、历史难复用。

建议展示：

- 一张问题链路图
- 3 个核心问题：
  - Prompt 门槛高
  - 结果不可直接用
  - 内容难以项目化复用

### 第 3 页：我的角色与方法

建议表达：

> 我在项目中独立完成竞品分析、用户访谈、痛点提炼、需求优先级、PRD、低保真原型和商业化测算。

建议展示方法链路：

```text
竞品分析 -> 用户访谈 -> 痛点归纳 -> 需求优先级 -> 产品方案 -> PRD -> 原型设计 -> 商业化测算
```

### 第 4 页：竞品分析

建议展示：

| 产品 | 类型 | 可借鉴点 | 主要问题 |
|---|---|---|---|
| 豆包 | 综合 AI 助手 | 上手门槛低 | 偏聊天式，项目管理弱 |
| Kimi | 长文本 AI 助手 | 长文总结强 | 创作模板不足 |
| 通义千问 | 综合大模型产品 | 场景覆盖广 | 功能入口复杂 |
| 即梦 AI | 视觉生成工具 | 视觉创作强 | Prompt 和参数门槛高 |

页面结论：

> 现有 AI 工具要么偏聊天，要么偏设计编辑，缺少面向高频内容生产者的“场景化生成 + 编辑 + 项目复用”一体化工作台。

### 第 5 页：用户研究

建议展示 5 位访谈对象：

| 用户 | 类型 | 代表场景 |
|---|---|---|
| U1 | 应用统计研一学生 | 求职准备 |
| U2 | 金融专硕学生 | 金融岗位求职 |
| U3 | 游戏主播/新媒体运营 | 内容创作 |
| U4 | 证券行业新人 | 专业办公 |
| U5 | 腾讯业务运营实习生 | 运营方案和汇报 |

建议突出：

- 样本虽然不大，但覆盖学习、求职、创作和办公场景。
- 研究目标是验证早期 MVP 方向，而不是做大规模定量研究。

### 第 6 页：核心洞察与痛点

建议展示痛点矩阵：

| 痛点 | 用户表现 | 产品机会 |
|---|---|---|
| Prompt 门槛高 | 不知道如何描述背景和输出要求 | 表单化模板 |
| 结果不可直接用 | 第一版需要反复修改 | 快捷改写、多版本 |
| 专业内容不可信 | 金融/证券内容需要核验 | 来源提示、风险提醒 |
| 历史难复用 | 对话记录无法按项目沉淀 | 项目化历史管理 |
| 流程断裂 | 生成后还要复制到其他工具 | 工作台式编辑区 |

### 第 7 页：产品定位与目标用户

一句话定位：

> 面向高频内容生产者的场景化 AI 创作工作台，让 AI 输出从“能生成”走向“能交付、能复用”。

目标用户优先级：

- P0：求职学生、内容创作者、运营/职场办公用户
- P1：专业行业用户、内容创作者、运营/职场办公用户
- P2：团队协作用户

### 第 8 页：核心功能方案

建议展示 5 个核心模块：

| 功能模块 | 解决痛点 |
|---|---|
| 场景化 Prompt 模板 | 降低输入门槛 |
| 快捷改写与多版本生成 | 提高结果可用性 |
| 结构化编辑区 | 承接生成后的修改 |
| 项目化历史管理 | 支持长期复用 |
| 专业内容核验提示 | 降低高风险内容误用 |

### 第 9 页：MVP 范围与优先级

建议展示：

| 优先级 | 功能 |
|---|---|
| P0 | 场景模板、表单化输入、生成结果、快捷改写、编辑区、基础项目保存 |
| P1 | JD 解析链路、账号风格模板、项目化历史、核验提示增强 |
| P2 | 视觉/课件生成、团队协作、数据看板 |

页面重点：

> MVP 不追求功能大而全，而是先验证“低门槛输入 + 可修改结果 + 可保存复用”的核心价值。

### 第 10 页：核心流程与低保真原型

建议展示用户流程：

```text
选择场景模板 -> 填写背景信息 -> AI 生成结果 -> 快捷改写/多版本 -> 保存项目 -> 导出使用
```

建议放 3-4 张低保真页面：

- 工作台首页
- 模板表单页
- 生成结果编辑页
- 项目管理页

### 第 11 页：PRD 摘要

建议展示一个典型功能：岗位 JD 解析。

内容包括：

- 输入字段：岗位 JD、目标岗位、用户背景、输出重点
- 输出结构：岗位职责、能力关键词、能力差距、简历建议、面试问题
- 状态规则：必填校验、生成中、生成失败、未保存离开提示
- 验收标准：能完成表单填写、生成结构化结果、保存到项目

页面重点：

> 展示你不只是会分析，还能把功能拆到页面、字段、状态和验收标准。

### 第 12 页：Token 成本与商业化

建议展示：

| 任务 | 单次估算成本 |
|---|---:|
| 轻量任务 | 约 0.005 元 |
| 标准任务 | 约 0.011 元 |
| 重度任务 | 约 0.028 元 |
| 多版本任务 | 约 0.024 元 |

套餐设计：

| 套餐 | 建议价格 | 核心权益 |
|---|---:|---|
| 免费版 | 0 元 | 基础模板、少量生成、3 个项目 |
| 学生求职版 | 19 元/月 | JD 解析链路、简历模板、20 个项目 |
| 专业版 | 39 元/月 | 多版本生成、账号风格、100 个项目 |
| 团队版 | 99 元/月起 | 项目共享、模板共享、团队空间 |

页面结论：

> 纯文本 MVP 的单次 Token 成本不高，付费点应围绕高级模板、多版本生成、项目管理和专业能力，而不是只卖生成次数。

### 第 13 页：项目价值与指标

建议展示：

| 指标 | 衡量目标 |
|---|---|
| 模板使用率 | 用户是否愿意从场景模板开始 |
| 首次生成采纳率 | 结果是否可用 |
| 快捷改写使用率 | 二次加工需求是否强 |
| 项目保存率 | 是否形成长期复用 |
| 7 日留存 | 是否成为持续工作台 |
| 会员转化率 | 商业化是否成立 |

### 第 14 页：项目总结与反思

建议表达：

- 这个项目帮助我完整走过 AI 产品从调研到落地的链路。
- 我将用户痛点转化为可执行功能，并用 P0/P1/P2 控制 MVP 范围。
- 后续如果继续迭代，会重点补充可点击原型、用户测试和更真实的成本/转化数据。

### 第 15 页：附录/链接

建议放：

- GitHub 仓库链接
- 完整 PRD
- 低保真原型文档
- 商业化分析文档
- 竞品分析和用户研究文档

## 4. 视觉排版建议

建议风格：

- 清爽、克制、偏产品汇报风
- 白底 + 深灰文字 + 蓝/绿色作为强调色
- 每页只讲一个重点，不堆长表格
- 多用流程图、矩阵、卡片、截图

建议比例：

- 研究分析：30%
- 产品方案：35%
- 原型/PRD：25%
- 商业化/总结：10%

## 5. 制作顺序

1. 先从现有 Markdown 文档提炼每页核心内容。
2. 选 4 张低保真页面放进原型展示页。
3. 将长表格压缩成 3-5 行关键结论。
4. 在封面和总结页突出个人背景：西安交通大学应用统计研一，目标 AI 产品经理实习。
5. 最后导出 PDF，并确保文件名包含姓名、学校和目标岗位。
