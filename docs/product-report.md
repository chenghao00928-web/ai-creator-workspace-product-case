# 产品方案报告

## 1. 产品概述

「AI 求职工作台」是一个面向求职学生的轻量 AI 产品 Demo。它不把 AI 当作泛聊天助手使用，而是围绕“岗位 JD 解析”这一高频求职任务，将目标岗位、岗位要求、个人背景和输出重点转化为结构化输入，帮助用户获得岗位职责拆解、能力关键词、能力差距、简历改写建议和面试准备问题。

本 MVP 的重点不是覆盖所有创作场景，而是验证一条清晰的求职准备链路：用户输入目标岗位和个人背景，系统通过场景化 Prompt 和大模型 API 生成可复用的分析结果，并支持复制、保存和后续项目化管理。项目同时补充竞品分析、用户研究、PRD、低保真原型、API 接入和 Token 成本测算，用于展示从需求洞察到 Demo 落地的完整产品思考过程。

产品核心目标：

- 降低求职学生理解岗位 JD 和撰写 Prompt 的门槛
- 将 AI 输出从泛泛建议收敛为稳定的求职分析结构
- 帮助用户把个人经历转化为更匹配岗位的简历表达
- 通过历史保存、成本测算和文档沉淀体现 AI 产品落地意识

一句话定位：

> 面向求职学生的 AI 求职工作台，让岗位 JD 分析从“看不懂要求”走向“知道差距、能改简历、能准备面试”。

## 2. 项目背景

当前主流 AIGC 工具已经具备较强的文本、图片和资料总结能力，但用户在真实使用中仍会遇到明显断点：

- 综合型 AI 助手上手简单，但多数仍以聊天框为主，缺少稳定的场景化引导。
- 设计类 AI 工具在模板、编辑和项目管理上更成熟，但不一定适合中文本土内容、求职和专业办公场景。
- 用户生成内容后，往往还需要复制到文档、剪辑、PPT、题库或发布平台中继续修改。
- 历史记录大多停留在对话列表，不方便按岗位、账号或项目长期复用。

因此，本项目希望探索一种更贴近真实工作流的 AI 创作工具：既保留 AI 生成效率，也强化模板、编辑、项目管理和可信核验能力。

## 3. 目标用户

### 3.1 MVP 核心目标用户

| 用户类型 | 典型任务 | 核心需求 | 优先级 |
|---|---|---|---|
| 求职学生 | JD 分析、简历润色、面试准备 | 快速理解岗位要求，把经历改写成更匹配岗位的表达 | P0 |
| 产品 / 运营 / 数据分析方向求职者 | 竞品分析、作品集表达、面试问题准备 | 将项目经历转化为岗位匹配表达 | P0 |
| 数据分析 / 产品 / 运营方向实习求职者 | 岗位能力拆解、项目经历包装、投递管理 | 识别能力差距并准备求职材料 | P0 |

### 3.2 扩展目标用户

| 用户类型 | 典型任务 | 核心需求 | 优先级 |
|---|---|---|---|
| 内容创作者 / 新媒体运营 | 视频脚本、标题、直播话术、发布文案 | 提高内容产出效率，保持账号风格和平台适配 | P1 |
| 运营/职场办公用户 | 运营方案、会议纪要、汇报材料、资料整理 | 快速生成结构化初稿，并沉淀项目背景和历史材料 | P1 |

## 4. 用户痛点

| 痛点 | 具体表现 | 产品机会 |
|---|---|---|
| Prompt 门槛高 | 用户知道想要什么，但不知道如何描述背景、风格和输出格式 | 提供场景化模板、表单化输入和示例 Prompt |
| 生成结果不可直接用 | AI 常给出第一版内容，但需要反复追问和人工改写 | 提供快捷改写、多版本生成和结构化编辑区 |
| 专业内容不可信 | 金融、证券等专业场景中用户担心内容错误或不严谨 | 增加来源提示、风险提醒和人工确认 |
| 历史内容难复用 | 内容分散在对话记录中，难以按项目长期保存 | 提供项目化历史、标签、收藏、搜索和版本管理 |
| 创作流程断裂 | 用户需要在多个工具之间复制粘贴和二次加工 | 用工作台串联生成、编辑、保存、复用和导出 |
| 付费价值感不清晰 | 用户不愿只为更多次数付费，更在意效率和可交付结果 | 将会员权益绑定高级模板、批量生成、项目管理和专业能力 |

## 5. 产品目标

### 5.1 用户目标

- 新手用户不需要掌握复杂 Prompt，也能完成高质量内容生成。
- 高频创作者可以快速获得多个版本，并保留自己的账号或项目风格。
- 职场用户可以把 AI 生成内容沉淀为项目资产，而不是一次性对话。
- 专业办公用户可以看到必要的核验提示，降低直接使用 AI 内容的风险。

### 5.2 业务目标

- 通过场景模板提升用户首次使用成功率。
- 通过编辑区和项目管理提升用户留存。
- 通过高级模板、批量生成、项目容量和专业能力建立付费理由。
- 以求职、内容创作和运营办公作为 MVP 主场景，逐步扩展到专业办公。

## 6. 核心功能设计

### 6.1 场景化 Prompt 模板

用户不再从空白聊天框开始，而是从具体场景入口进入。

MVP 场景模板：

- 岗位 JD 解析
- 简历润色
- 视频脚本生成
- 运营方案生成
- 会议纪要整理

模板输入字段示例：

| 字段 | 说明 |
|---|---|
| 任务目标 | 用户希望 AI 完成什么 |
| 背景信息 | 岗位、账号、业务、受众或材料背景 |
| 输出格式 | 表格、清单、正文、脚本、方案 |
| 风格要求 | 专业、口语化、有网感、正式、适合学生理解 |
| 使用场景 | 投递简历、发布视频、汇报、课堂讲解等 |

### 6.2 快捷改写与多版本生成

生成结果旁提供快捷操作，减少用户反复写追问的成本。

常用操作：

- 更专业
- 更口语化
- 更有网感
- 改短
- 扩写
- 生成 3 个版本
- 提炼标题
- 转成汇报口吻

### 6.3 结果结构化编辑区

生成结果进入可编辑工作区，而不是只停留在聊天气泡中。

编辑区可以按内容类型拆分：

| 内容类型 | 编辑结构 |
|---|---|
| 简历优化 | 岗位关键词、经历改写、能力差距、面试问题 |
| 视频脚本 | 选题、开头、正文、互动话术、标题标签 |
| 运营方案 | 背景、目标、策略、执行步骤、指标 |
| 会议纪要 | 结论、待办、负责人、时间节点 |

### 6.4 项目化历史管理

用户可以把内容保存到项目，而不是散落在对话历史里。

项目类型示例：

- 求职项目：按公司、岗位、JD、简历版本保存
- 内容账号项目：按平台、栏目、选题和脚本保存
- 运营项目：按活动、方案、复盘和汇报材料保存
- 教学项目：按学科、年级、章节和试题保存

### 6.5 专业内容核验提示

在高风险内容中加入轻量提醒，提升用户信任。

适用场景：

- 金融、证券、法律等专业内容
- 数据、结论、教材知识点和考试题解析
- 可能影响用户决策或学习结果的输出

提示方式：

- 标记“建议核验”的关键结论
- 提醒补充来源或教材依据
- 对不确定内容给出风险提示
- 保留人工确认入口

## 7. MVP 版本范围

### 7.1 MVP 必做

| 模块 | 功能 | 说明 |
|---|---|---|
| 场景入口 | 岗位 JD 解析、简历润色、视频脚本、运营方案、会议纪要 | 覆盖求职、创作和办公三类核心用户 |
| 表单化 Prompt | 背景、目标、风格、输出格式 | 降低新手输入门槛 |
| AI 生成结果 | 根据模板生成结构化内容 | 保证核心生成链路跑通 |
| 快捷改写 | 改短、扩写、更专业、更口语化、多版本 | 提高生成结果可用性 |
| 编辑区 | 可编辑、复制、导出 | 让内容从聊天结果进入工作台 |
| 基础项目保存 | 保存到项目、收藏、搜索 | 支持简单复用 |
| 核验提示 | 专业内容轻量提醒 | 建立可信边界 |

### 7.2 MVP 暂不做

| 暂不做功能 | 原因 |
|---|---|
| 完整团队协作 | 早期用户以个人效率为主，协作可后置 |
| 数据看板 | 需要外部数据或长期使用数据支撑 |
| 复杂视觉编辑器 | 实现成本高，且不是第一阶段核心验证点 |
| 垂直行业知识库 | 需要外部数据源和合规评估，不宜一开始铺太大 |
| 深度行业数据库 | 专业场景先做风险提示和资料上传，后续再扩展 |

## 8. 核心使用流程

```mermaid
flowchart LR
    A["选择场景模板"] --> B["填写背景信息"]
    B --> C["AI 生成结构化结果"]
    C --> D["快捷改写或多版本生成"]
    D --> E["在编辑区整理内容"]
    E --> F["保存到项目"]
    F --> G["导出或复制使用"]
```

示例流程：岗位 JD 解析

1. 用户选择“岗位 JD 解析”模板。
2. 粘贴岗位 JD，填写目标岗位、已有经历和求职方向。
3. AI 输出岗位关键词、能力要求、能力差距、简历优化建议和面试问题。
4. 用户点击“更专业”或“生成 3 个简历版本”。
5. 用户将结果保存到对应公司/岗位项目中。

示例流程：视频脚本生成

1. 用户选择“视频脚本”模板。
2. 填写平台、账号定位、选题、目标受众和风格。
3. AI 输出脚本、开头钩子、标题、标签和互动话术。
4. 用户生成多个版本，对比后保存到选题项目。

## 9. 商业化设计

### 9.1 免费版

- 基础场景模板
- 基础生成次数
- 基础快捷改写
- 少量项目保存

### 9.2 会员版

- 高级场景模板
- 批量生成和多版本对比
- 更多项目空间和历史搜索
- 账号风格模板
- 专业内容核验提示增强
- 导出更多格式

### 9.3 商业化逻辑

用户付费理由不应只围绕“更多生成次数”，而应强调：

- 更快完成真实任务
- 更少重复修改
- 更稳定的风格和专业表达
- 更强的历史复用和项目管理
- 更适合具体行业场景的模板能力

## 10. 迭代规划

| 阶段 | 重点目标 | 主要功能 |
|---|---|---|
| MVP / P0 | 验证“模板 + 改写 + 编辑区”的核心价值 | 场景化 Prompt 模板、快捷改写、多版本生成、结构化编辑区、基础项目保存 |
| P1 | 强化场景深度和长期复用 | 岗位 JD 解析链路、账号风格模板、项目化历史管理、专业核验提示 |
| P2 | 扩展协作、视觉和数据能力 | 视觉/课件辅助生成、团队协作、模板共享、数据看板、效果追踪 |

## 11. 成功指标

| 指标 | 说明 |
|---|---|
| 模板使用率 | 用户是否愿意从场景模板开始任务 |
| 首次生成采纳率 | 用户首次生成后是否复制、保存或继续编辑 |
| 快捷改写使用率 | 用户是否通过快捷操作完成二次加工 |
| 项目保存率 | 用户是否把内容沉淀到项目中 |
| 次日/7 日留存 | 用户是否把产品作为持续工作台使用 |
| 会员转化率 | 用户是否愿意为高级模板、批量生成和项目管理付费 |

## 12. 总结

AI 创作助手工作台的核心价值，不是再做一个通用聊天助手，而是把 AI 能力嵌入真实创作流程中。通过场景化 Prompt 模板降低输入门槛，通过快捷改写和结构化编辑区提升结果可用性，通过项目化历史管理提升长期复用价值。

在 MVP 阶段，产品应优先服务求职学生、内容创作者和运营/职场办公用户，围绕高频且交付物明确的任务建立核心体验。专业场景具备较强潜力，但需要更明确的核验机制和边界提示，适合在 P1 阶段逐步扩展。
